# 客服会话与微信回复修复更新（20261107-195806）

本次更新管理后台前端和 Java API。小程序代码、数据库表结构、域名、证书、微信回调配置均不需要变更。发布包使用现有数据库和服务配置；不会初始化门店数据。

## 本次变化与验收范围

- 客户沟通默认显示全部状态。总部通过菜单、站内消息或桌面提醒进入时，会清除旧门店及搜索条件；门店账号仍只能查看授权门店。
- 列表与消息内容区分加载、空数据、加载失败，列表失败可以重试。自动打开首条会话，分页越界返回有效页面。
- 微信 JSON 响应即使标为 text/plain 也能读取。明确返回 errcode=0 才显示发送成功。
- 获取 access_token 时就失败，会显示配置原因及微信错误码；没有提交微信的消息不消耗回复次数。请求提交后未取得明确结果仍显示待核实，避免自动重发造成重复消息。
- 自动测试使用隔离数据库和模拟微信接口。云服务器运行与真实微信送达需在更新后验收。

## 2. 替换 Java 容器

先确认目前 Java 容器的实际名称：

```bash
docker ps --format '{{.Names}}  {{.Image}}  {{.Status}}'
```

你最近给出的运行中 Java 容器名称为 yuhetang-java-api-failed-20261107-182144。名称带 failed 但当时状态为 healthy；不要因为名称删除它。如果已变更，请将下面 YHT_OLD_JAVA 改成当前 Java 容器名。不要填 OpenResty 或 MySQL 容器名。

```bash
YHT_OLD_JAVA=yuhetang-java-api-failed-20261107-182144
docker inspect --format '{{.Name}}  {{.Config.Image}}  {{.State.Status}}' "$YHT_OLD_JAVA"
install -d -o root -g root -m 0700 /var/backups/yuhetang-chat-20261107-195806
install -o root -g root -m 0600 /etc/yuwatang-reservation.docker.env /var/backups/yuhetang-chat-20261107-195806/
docker stop --time 50 "$YHT_OLD_JAVA"
docker rename "$YHT_OLD_JAVA" yuhetang-java-api-before-20261107-195806
bash run.sh yuhetang-java-api:20261107-195806
```

新容器启动后检查：

```bash
docker logs --tail 60 yuhetang-java-api
curl --fail --silent --show-error --max-time 10 http://127.0.0.1:8790/api/health
docker inspect --format '{{.State.Health.Status}}' yuhetang-java-api
```

Java 启动需要一段时间；首次显示 starting 时，稍后再检查。应返回 status=ok、database=connected，容器变为 healthy。此次没有新增数据库迁移，旧容器保留用于回退。现有 MySQL、上传文件和网站继续使用。

## 4. 真实客服验收

1. 客户重新从小程序进入客服，发送一条新的测试消息。
2. 管理后台点击“客户沟通”。总部默认全部门店、全部状态；确认左侧有会话、右侧有消息内容。
3. 回复一条消息，确认客户端实际收到。
4. 如果显示“消息尚未提交微信”，按页面给出的错误码处理 AppSecret、服务器出口 IP 白名单等配置；不要把密钥贴到聊天中。
5. 如果仍显示“发送结果待核实”，先确认客户端是否收到，再查看这条消息状态。不要反复点击发送相同内容。

本次验收不要求重新审核发布小程序，也不修改已启用的 booking.hetuonian.cn 回调。
