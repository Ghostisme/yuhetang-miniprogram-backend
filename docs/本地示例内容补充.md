# 本地示例内容补充到线上

本包将本地管理 API 中剩余的示例内容补到服务器，方便在管理后台找到并逐项调整。包括首页标题、简介、封面、品牌故事、联系提示、4 个品牌养护介绍、2 个品牌产品、2 组空间相册、33 张图片素材，以及 9 店共 27 位示例调理师。

| 内容 | 后台位置 | 导入策略 |
| --- | --- | --- |
| 首页、品牌故事、联系提示 | 品牌与内容 | 只填空字段，保留已有文案、配色与开关 |
| 4 个品牌养护介绍 | 品牌与内容 → 全部门店 → 养护项目 | 只补缺少的 ID，供首页品牌展示 |
| 2 个品牌产品 | 品牌与内容 → 品牌产品 | 只新增缺少的 ID |
| 2 组空间相册 | 品牌与内容 → 空间相册 | 补充品牌相册，保留各店相册 |
| 33 张素材 | 图片素材 | 按文件校验值复用；新上传标题以“示例素材-”开头 |
| 27 位示例调理师 | 调理师管理 → 各门店 | 每店 3 位，保留姓名中的“示例”和 `sample=true` 标识 |

4 个品牌介绍使用本地的“蕲艾温养、经络舒缓、足下轻盈、东方刮痧”；2 个产品是“蕲春陈艾、草本日常”；2 组相册是“迎客与茶席、静养与休憩”。它们是可编辑的示例内容，具体文字和图片请按客户实际情况调整。调理师示例不是实际员工资料，也不代替实际资质确认。

## 与前一批资料的顺序

先完成 `20261108-125710` Java 更新和客户品项独立初始化，再运行本补充包。脚本要求 9 店均为 `catalogMode=INDEPENDENT`，且已存在本店专属项目；不符合就停止。

前一批已有的门店地址、营业时间、电话、相册、135 条独立品项及价格、9 张价目图、预约规则均保留。品牌示例不会加进这些门店的独立目录。新建的示例调理师关联本店全部已上架的专属品项 ID，便于逐项测试调理师意向；未上架或待确认的项目不添加。例如梅花路店没有足疗，就不会给该店示例调理师分配足疗。姓名中的“示例”与来源标记保留，真实员工的可服务范围由运营人员确认维护。

早期初始化已存在的示例老师只关联了推拿、悬灸、足疗、刮痧等少数项目，重复运行本补充工具会保留已有资料。需要补齐这一批已有示例老师时，使用[调理师意向修复](调理师意向修复.md)中的独立脚本，无需再次导入全部内容或更新 Java。

此包是纯数据包，通过现有 Java 管理 API 保存数据。无需替换 JAR、重建 Docker、改 OpenResty、上传管理后台前端或重新审核小程序。

## 上传和执行

本轮生成的文件名中，`@RELEASE_ID@` 会替换为实际编号。将以下两个文件上传到 `/home/ubuntu/`，不要放入网站目录：

- `yuhetang-local-content-@RELEASE_ID@.zip`
- `yuhetang-local-content-@RELEASE_ID@.zip.sha256`

先在 ubuntu 终端执行：

```bash
cd /home/ubuntu
sha256sum --check yuhetang-local-content-@RELEASE_ID@.zip.sha256
sudo install -d -o root -g root -m 0700 /root/yuhetang-upload
sudo python3 -m zipfile -e yuhetang-local-content-@RELEASE_ID@.zip /root/yuhetang-upload
sudo -i
```

进入 root 后再执行：

```bash
cd /root/yuhetang-upload/yuhetang-local-content-@RELEASE_ID@
sha256sum --check SHA256SUMS
python3 tools/initialize-local-content.py --validate-only
python3 tools/initialize-local-content.py --username admin
```

最后一条只预览，不写业务数据。提示密码时输入管理后台的总部账号密码，不是服务器 root 或 MySQL 密码，输入时不回显。账号不是 `admin` 时改成实际账号。

预览会显示补充字段、可复用图片、待上传图片、待新建与保留的示例调理师数量。随后正式执行：

```bash
python3 tools/initialize-local-content.py --username admin --apply
```

成功末尾出现 `Verified` 和 `Branch data preserved`。首次空白系统通常会新建 27 位示例调理师和上传 33 张素材；已有相同内容时，新增数量减少。

如果显示 `brand content=publish`，补充内容已发布，重新进入小程序即可读取。如果显示 `brand content=draft`，说明原来存在未发布编辑，脚本已将补充项合并到草稿；到“品牌与内容”核对后点击“发布”，保留人工决定原草稿何时上线。

## 保留修改、备份与重复执行

- 每次正式导入前，在本包 `backups/local-content/<时间编号>/before.json` 保存品牌草稿、公开内容、门店资料、品项、规则、素材元数据及已有调理师；`report.json` 记录上传结果、实际调理师 ID 和执行进度。
- 已有内容 ID 对应的整条资料保留，首页已填写的字段保留，已有调理师不改名、不调等级、不改上下架。导入的示例调理师有来源标记，之后改名或改为真实员工，再运行也会复用原记录。
- 同一批原样重复运行不会重复上传或新建。人为删除的示例内容再次运行会补回；因此日常维护直接在后台修改，不需要反复执行初始化。
- 通过当前登录权限与版本号检测并发编辑。遇到冲突、失败或来源歧义就停止并保留进度；跨内容、图片和调理师的导入不是单个数据库事务，不自动删除已成功创建的数据。
- 本包只包含已确认的示例内容和图片，没有数据库文件、密码、Token、账号、角色、客服对话或通知配置。本地实际客户、预约记录均为 0；旧源码内未启用的历史预约演示数组不导入。
