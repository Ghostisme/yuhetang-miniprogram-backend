# 微信客服诊断更新：20261107-215000

适用当前服务器：`yuhetang-java-api:20261107-195806`、独立 MySQL `127.0.0.1:3307/yuwatang_reservation`、客服回调 `https://booking.hetuonian.cn/api/wechat/customer-service`。

本次解决的是后台吞掉具体发送异常的问题，并补充已验签回调的处理结果日志。尚未确认微信文字丢失的根因；真实收发必须按文末步骤验收。用户已确认没有开通云开发，该项分流假设已排除，详见[微信客服回调检查](微信客服回调检查.md)。

## 一、准备新 Java 镜像

从本地 `yuhetang-miniprogram-admin/releases` 上传以下两个文件到服务器 `/home/ubuntu`：

- `yuhetang-java-docker-20261107-215000.tar.gz`
- `yuhetang-java-docker-20261107-215000.tar.gz.sha256`

执行 `sudo -i` 进入 root，再执行整段：

```bash
bash -e <<'YHT_PREPARE'
cd /home/ubuntu
sha256sum --check yuhetang-java-docker-20261107-215000.tar.gz.sha256
install -d -o root -g root -m 0700 /root/yuhetang-upload
tar -xzf yuhetang-java-docker-20261107-215000.tar.gz -C /root/yuhetang-upload
cd /root/yuhetang-upload/yuhetang-java-docker-20261107-215000
sha256sum --check SHA256SUMS
docker build -t yuhetang-java-api:20261107-215000 .
docker run --rm --network none \
  --env-file /etc/yuwatang-reservation.docker.env \
  --entrypoint /bin/bash \
  yuhetang-java-api:20261107-215000 /app/check-db-target.sh
YHT_PREPARE
```

此步骤构建镜像和校验连接目标，不启动 Java，不连接数据库。若失败，先处理报错，保留当前服务。

## 二、切换 Java 容器

本次没有新增数据库迁移，保留现有环境文件、独立 MySQL、上传目录及两套网站。切换时 Java 接口会短暂中断。以下命令先保留旧容器，再启动新版本；启动命令失败时自动恢复旧 Java。

```bash
bash -e <<'YHT_SWITCH'
cd /root/yuhetang-upload/yuhetang-java-docker-20261107-215000
docker inspect --format 'Current image: {{.Config.Image}}' yuhetang-java-api
if docker container inspect yuhetang-java-api-before-20261107-215000 >/dev/null 2>&1 ||
   docker container inspect yuhetang-java-api-failed-20261107-215000 >/dev/null 2>&1; then
  printf 'A backup or failed container name already exists. Stop here and inspect it first.\n' >&2
  exit 1
fi
docker stop --time 50 yuhetang-java-api
if ! docker rename yuhetang-java-api yuhetang-java-api-before-20261107-215000; then
  docker start yuhetang-java-api
  exit 1
fi
if ! bash run.sh yuhetang-java-api:20261107-215000; then
  if docker container inspect yuhetang-java-api >/dev/null 2>&1; then
    docker stop --time 50 yuhetang-java-api
    docker rename yuhetang-java-api yuhetang-java-api-failed-20261107-215000
  fi
  docker rename yuhetang-java-api-before-20261107-215000 yuhetang-java-api
  docker start yuhetang-java-api
  exit 1
fi
docker ps --format '{{.Names}}  {{.Image}}  {{.Status}}'
YHT_SWITCH
```

启动通常需要几十秒。稍后执行下面两条，确认版本和健康状态：

```bash
docker inspect --format '{{.Config.Image}}  {{.State.Health.Status}}' yuhetang-java-api
curl --fail --silent --show-error --connect-timeout 3 --max-time 8 http://127.0.0.1:8790/api/health
```

应看到 `yuhetang-java-api:20261107-215000`、`healthy`，以及 `database=connected`、`status=ok`。若仍为 `starting`，稍后再查；若为 `unhealthy` 或健康请求持续失败，执行文末回退。

## 三、验证真实客服

用客户微信发送一条新文字，然后读取这次 Java 日志。当前小程序未开通云开发，无需检查或开通云开发配置：

```bash
docker logs --since 10m --tail 200 yuhetang-java-api 2>&1 |
  grep -E 'WeChat callback|WeChat customer send'
```

- `type=event event=user_enter_tempsession outcome=ENTRY`：只进入了客服窗口。
- `type=text event=none outcome=STORED`：客户文字已入库，应在后台出现。
- `outcome=DUPLICATE`：同一消息的重复推送已去重。
- `outcome=REJECTED` / `ERROR`：用同一行 HTTP 状态或异常类别定位。
- 只有进入事件、没有文字回调：继续检查微信文字的实际投递路径。

后台出现这条新文字后，再回复一次。新的失败气泡将显示响应超时、TLS 失败、HTTP 状态或响应解析失败等具体原因；日志里的 `category` 与该原因对应。未知结果不会自动重发，旧的两条 `UNKNOWN` 历史也不会自动改成成功。以客户手机实际收到这次新回复作为发送验收。

门店资料另用 `yuhetang-official-stores-20261107.zip` 导入，Java 更新不自动填充门店。操作见[官网门店初始化](官网门店初始化.md)。

## 回退到更新前的 Java

仅在新版本未通过健康或业务验收时执行；保留失败容器供排查：

```bash
bash -e <<'YHT_ROLLBACK'
docker container inspect yuhetang-java-api-before-20261107-215000 >/dev/null
if docker container inspect yuhetang-java-api-failed-20261107-215000 >/dev/null 2>&1; then
  printf 'The failed container name already exists. Stop here and inspect it first.\n' >&2
  exit 1
fi
docker stop --time 50 yuhetang-java-api
docker rename yuhetang-java-api yuhetang-java-api-failed-20261107-215000
docker rename yuhetang-java-api-before-20261107-215000 yuhetang-java-api
docker start yuhetang-java-api
YHT_ROLLBACK
```

此版本与原版数据库结构一致，回退只切换 Java 容器，不恢复或清空数据库。若同名 `failed` 容器已存在，先检查它，不重复执行覆盖。
