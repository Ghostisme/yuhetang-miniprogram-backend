# 会员跨店预约与支付预留

会员可以预约其他已开放的门店；项目、价格核实、时段、名额和调理师均以本次接待门店为准。会员归属门店与接待门店分别记录，不因跨店预约改变会员档案。当前只建立结算预留，不发生任何真实扣款或跨店划账。

## 会员身份与门店归属

客户使用微信授权手机号，关联 `customer_account` 和 `customer_profile`。只有授权手机号与预约联系电话一致、且档案已由后台核实为会员时，才保存已核实会员快照。客户勾选“是会员”、提交额外会员字段或更换为他人手机号，均不能自行获得已核实身份。后台代客预约使用已知客户档案；分店账号不能维护总部会员状态与归属。

总部在“客户档案”中核实会员状态、等级及归属门店。未确认归属门店的会员仍可预约，但不能登记会员储值结算。`appointment_membership` 保存预约当时的核实状态、等级、会员归属门店和接待门店；跨店标识由服务端推导。总部后续调整会员归属，不覆盖历史预约快照；旧快照与当前归属不一致时，储值结算预留会拒绝并要求总部核实。

已有预约增量建立 `LEGACY_UNKNOWN` 快照，不按当前会员状态猜测过去身份。对客户和分店展示的快照不含私有客户档案 ID。其他门店仍不能读取本店预约和客户私有资料。

## 结算数据和状态

每条预约对应一条 `reservation_payment`，分别保存 `member_store_id` 和 `service_store_id`。金额 `amount_fen` 以人民币整数分记录，允许待核价时为空；确认金额须为 1 至 999999999 分。项目中的价格描述、区间和“起”价格不自动转换为扣款金额，需接待门店核实总价。

| 字段 | 取值和含义 |
| --- | --- |
| channel | `UNSELECTED` 待确认、`MEMBER_BALANCE` 会员储值预留、`WECHAT_PAY` 微信支付预留 |
| status | `UNPRICED` 待核价、`RESERVED` 已登记金额、`CLOSED` 预约取消或未到店后关闭 |
| settlement_status | `NOT_STARTED` 未结算、`RULES_PENDING` 跨店储值分摊规则待配置 |
| mode | 固定 `RESERVATION_ONLY` |
| paymentEnabled / canPay | 固定 `false` |

预约取消或标记未到店时关闭结算预留。同行人数变更后清空原核价金额，要求重新核价；接待与会员归属快照保留。金额和方式修改写入 `reservation_payment_event` 与审计记录。保存接口同时核对预约版本和结算版本，并使用共享预约锁与幂等标识处理并发、重复提交和连接中断后的重试。

## 接口与权限

所有业务接口沿用现有 Bearer 登录认证、门店隔离和客户所有权校验。

| 接口 | 用途与权限 |
| --- | --- |
| `GET /api/payment-capabilities` | 返回两种通道尚未启用、跨店结算未启用 |
| `GET /api/admin/appointments/{id}/payment` | 接待门店读取结算，须 `payments:read` |
| `PUT /api/admin/appointments/{id}/payment` | 接待门店登记核价和方式，须 `payments:write` |
| `GET /api/me/appointments/{id}/payment` | 客户读取本人预约结算 |
| `POST /api/me/appointments/{id}/payment/start` | 未来支付入口；当前合法请求返回 501，不产生支付或账务状态 |

登记请求包含 `amountFen`、`channel`、`version` 和 `appointmentVersion`，请求头须含 8 至 100 位字母、数字、短横线或下划线组成的 `Idempotency-Key`。同一操作重试沿用原 key 和内容；同一 key 更换内容返回 409。不得凭 HTTP 超时自动生成新 key 并重复记账。自定义角色需按需授予新增权限；升级只给已有内置总部和店长角色读写权限、前台角色读取权限，不扩大自定义角色权限。

`PaymentPort` 留出了支付请求、金额、币种、会员归属、接待门店、付款人和幂等标识。当前 `ReservedPaymentPort` 不调用支付网关，不生成假支付成功结果。将来启用微信支付前须实现真实下单、签名验签、回调去重、查单及退款；启用储值跨店扣款前须实现余额账本、扣减与冲正、分摊和跨店对账。当前没有真实支付按钮，也没有可直接开启这些能力的配置开关。

## 部署与验证范围

V13 通过既有 Flyway 管理，仅修改本项目业务库，新增三张业务表与两项权限；不重置门店、品项、客户或预约。使用整体更新包更新 Java 和后台，再上传配套小程序。已导入的数据无需再次初始化。

`CrossStoreIntegrationTest` 在独立 H2 中覆盖会员与非会员跨店预约、身份伪造、联系电话变化、未知归属、总部归属修改、分店权限、门店调理师约束、金额精度、幂等重试、并发版本冲突、取消关闭、人数变更重新核价，以及两种真实支付入口保持关闭。管理后台浏览器验证覆盖核价、连接失败后保留提交 key、权限与移动端布局。小程序以中文、英文和日文验证跨店展示及更换手机号后的身份回退。

这些是本地接口和隔离浏览器测试，不代表已在腾讯云 MySQL 或 Docker 实测，也不替代真机手机号授权与消息送达测试。真实微信支付、会员余额扣减、退款及跨店清结算当前均未接入。
