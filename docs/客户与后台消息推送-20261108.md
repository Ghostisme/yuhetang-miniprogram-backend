## PC 消息中心

消息中心区分“客户消息推送”和“管理后台消息推送”，两组分别显示渠道、配置状态和发送记录。总部选择门店后配置本店开关，门店账号受 RBAC 和本店范围限制；只有查看权限的账号可以读消息，不能更改渠道或获取完整短信接收电话。

后台铃铛显示预约和客户咨询的未读数。预约已读状态按后台账号分别保存；当前范围全部已读只影响当前账号和刷新时刻以前的消息，不会替同事已读，也不会消除客户咨询的未读状态。点击预约通知后按预约编号定位预约列表。

“PC端消息通知 → 开启 / 测试桌面提醒”需要浏览器允许通知。前台约 15 秒、隐藏标签页约 30 秒检查一次，带随机间隔和失败退避。Chrome / Edge 同一浏览器多个标签页通过共享记录与浏览器锁避免重复桌面提醒。浏览器关闭、电脑休眠或系统限制后台计时后不保证桌面提醒，应由店长微信或短信覆盖这些场景。

## 客户配合后接店长服务号

### 1. 确认权限和模板

使用新服务号管理员确认该账号已认证、具有模板消息与网页授权权限。模板库中搜索“新预约通知”“预约待处理通知”“待办事项提醒”等业务关键词，选择与实际类目和门店预约待办相符的模板；这些是搜索建议，不是保证存在的模板名称或 ID。

优先选能够表达门店、预约时间、预约项目、客户称呼、待办事项/处理状态的字段。选用后提供完整私有模板 ID、每个字段的键及名称，例如 `thing1=门店`；不要只提供模板名称或公共编号。字段键按实际模板填写。

### 2. 服务器白名单与网页授权域名

服务号 IP 白名单加入 `43.142.125.157`。网页授权域名填写 `mp-admin.hetuonian.cn`，不带协议、端口或 `/admin`。

JS 接口安全域名用于微信 JS-SDK，网页授权域名用于 OAuth 获取服务号身份。当前绑定通过服务器 OAuth 完成，不要求先开发 JS-SDK。服务号“消息推送 URL / Token / AESKey”是接收服务号入站事件的配置，不能替代 AppSecret、模板与网页授权，也不能用旧酷鼠回调作为本项目是否接通的依据。

若微信要求校验文件，把下载的原始文件放在填写域名所对应的站点根目录。当前已知文件名为 `MP_verify_l52TiArcmfHnXVfa.txt`：

```bash
sudo install -o root -g root -m 0644 /home/ubuntu/MP_verify_l52TiArcmfHnXVfa.txt /opt/1panel/www/sites/mp-admin/index/MP_verify_l52TiArcmfHnXVfa.txt
curl --noproxy '*' --max-time 10 -i https://mp-admin.hetuonian.cn/MP_verify_l52TiArcmfHnXVfa.txt
```

必须返回原始文件的内容。HTTP 200 但返回 HTML 仍是失败；本次检查时该路径曾被前端 SPA 回退为 455 字节 HTML，需要先完成原文件上传。后续网页授权页要求其他文件时同样原样上传。网站已有 `root` 应当指向该静态目录，正常的 `try_files $uri $uri/ /index.html` 会优先读取实际存在的文件；全路径反向代理需要为校验文件保留静态访问。

### 3. 配置 Java 环境

本次同时提供 `configure-staff-wechat.py` 及 `.sha256`。上传至 `/home/ubuntu` 后交互执行：

```bash
cd /home/ubuntu
sha256sum --check configure-staff-wechat.py.sha256
sudo python3 configure-staff-wechat.py --app-id wxf9ad4dfd7684097a
```

按提示在终端输入服务号 AppSecret、完整模板 ID 和 `https://mp-admin.hetuonian.cn`。AppSecret 不回显，不写入命令行或聊天。字段映射可以此时填写 JSON，也可以留空后由总部在“扩展与配置”填写。例子只说明格式，键必须替换为实际模板字段：

```json
{"thing1":"storeName","time2":"time","thing3":"serviceName","thing4":"customerName","thing5":"eventLabel"}
```

允许的业务字段：`storeName`、`serviceName`、`customerName`、`time`、`status`、`appointmentId`、`event`、`eventLabel`。其中 `eventLabel` 为“新预约申请”等中文事项名称；不要把英文事件编码映射到面向店长的事项字段。

工具仅更改 `/etc/yuwatang-reservation.docker.env` 的服务号字段和 `PUBLIC_URL`，原文件另存 root 私密备份。它不改数据库连接、小程序 AppSecret 或客服 Token。环境变量 `SERVICE_TEMPLATE_MAPPING` 仅在数据库尚无总部映射时初始化；已有总部映射以后台保存内容为准。

用本版本激活脚本加 `--reload-env` 重建 Java 容器，再进入“消息中心 → 管理后台消息推送 → 检查店长服务号配置”。普通 `docker restart` 不会读取编辑后的 env 文件。配置检查只获取微信模板，不发送客户或店长消息。

### 4. 各门店本人绑定

总部创建或确认本店店长后台账号并授予通知权限。进入消息中心选择门店和本店有效接收账号，生成 15 分钟绑定链接，由接收人本人在微信打开、关注正确服务号并点击确认。OAuth 回调是 `https://mp-admin.hetuonian.cn/api/wechat/service/callback`；与小程序客服回调分开。

每店当前支持一位微信接收人。链接一次使用，重复确认、过期、门店或人员不匹配会拒绝；更换或解绑后旧待发消息不会转给新人员。店长无需每条预约反复点击小程序的一次性订阅；服务号发送仍需满足认证、模板权限、关注状态及微信平台规则。
