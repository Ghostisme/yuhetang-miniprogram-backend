# 三仓库开发与发布

当前开发入口为以下三个独立仓库。原 yuwatang-reservation 目录及迁移前备份保留，业务资料不随源码迁移。

| 本地目录 | 技术与用途 | 检查和产物 |
| --- | --- | --- |
| D:/github_code/裕和堂相关项目/yuhetang-miniprogram | Taro + React + TypeScript；客户小程序和 H5 | npm run check:mini；build:weapp → dist/weapp；build:h5 → dist/h5 |
| D:/github_code/裕和堂相关项目/yuhetang-miniprogram-admin | React + TypeScript + Vite + Ant Design；管理后台 | npm run build → dist；npm run package:release → releases |
| D:/github_code/裕和堂相关项目/yuhetang-miniprogram-backend | Java 17 / Spring Boot；API、数据库迁移与部署 | mvn -B -ntp -Papi-release verify → target-api/reservation-api-1.0.0.jar |

工程可放在不同目录。构建、素材、运行配置和发布包均从各自仓库读取，不自动调用相邻工程。客户 H5 由 Taro 编译，后台根路径和 /admin 都进入管理界面。Java 不提供 HTML 页面。

## 本地联调

后端运行 tools/start-local.ps1 -Build 或 mvn spring-boot:run，默认 API 8790，仅使用本仓库独立数据。后台 npm run dev 默认 5181；Taro npm run dev:h5 默认 5182。两个前端通过 API_PROXY_TARGET 配置代理目标，默认指向 http://127.0.0.1:8790。

Taro 使用 src/app.tsx、src/app.config.ts、config/index.ts 和 src/pages。每个页面包含 index.tsx、index.scss、index.config.ts；不直接修改 dist。微信开发者工具导入仓库根目录，project.config.json 指向 dist/weapp，先运行 npm run dev:weapp 或 build:weapp。

生产编译 API 默认 https://booking.yuhetangtcm.com，可用 TARO_APP_API_BASE 覆盖。本地模拟登录须显式配置 TARO_APP_DEV_LOGIN=true，且只连接 local 后端；正式构建始终禁用。生产 H5 当前提供公开内容浏览，客户登录和预约等身份能力使用微信小程序验收。

## 各自构建与发布

后台仓库：

```powershell
npm ci
npm run build
npm run package:release
```

后端仓库：

```powershell
mvn -B -ntp -Papi-release verify
python tools/package-1panel.py --java-runtime D:/deploy/java17-linux-x64.tar.gz
```

Java 运行包需匹配打包脚本固定的 SHA256；自行准备后通过参数指定。两个打包脚本默认使用 YYYYMMDD-HHMMSS 唯一编号，支持 --release-id，不覆盖旧发布包。ZIP/TAR 和校验文件位于各自忽略的 releases/。

需要联合检查反向代理时，后端可运行 python tools/verify-1panel-split.py --frontend-dist D:/deploy/admin-dist，显式指定已构建的后台目录。这是可选验收，不是后端构建依赖。它使用独立 H2 内存库和本机 Windows Nginx，不连接业务库、不发送外部消息。

后端 Dockerfile 仅需本仓库作为上下文；Compose 同样只构建本仓库。默认不包含数据库、密钥或本地生成产物。当前云端采用 Java systemd 服务和 1Panel 静态网站，Compose 为可选方案。

## 分别更新

后台静态文件发布到 mp-admin.yuhetangtcm.com，/api/ 代理 Java；API 使用 booking.yuhetangtcm.com；仅客服回调使用 booking.hetuonian.cn。保留现有后台域名，详见 [1Panel 操作说明](../deploy/1panel/README.md)。

只更新后台时重新部署其静态文件；只更新 Java 时备份本项目数据、配置和旧 JAR，再独立替换重启。不要重新执行首次安装 prepare.sh。门店、品项、内容和已支持的预约规则走后台/API 更新；客户端新增页面、交互和原生能力仍需小程序发布。

真实业务数据、环境配置、证书、日志、备份和压缩包不提交 Git。本次本地验收不代表云端已升级、真实微信已送达或 5 万同时在线已通过压测。
