# 客户资料、会员标识与来源

## 使用入口

客户在小程序完成微信登录后，“我的预约”显示客户资料卡。首次登录即写入微信账号记录、首次登录时间和最近登录时间；客户尚未预约时，总部也能在“客户档案”看到这条登记。

资料卡填写姓名或称呼，勾选用途说明后点击“微信授权手机号并保存”。微信登录和手机号授权是两个动作：`wx.login` 不会返回手机号或真实姓名。姓名由客户填写，不代表实名核验；手机号由微信原生授权按钮取得一次性 `code`，Java 调用微信手机号接口交换，不接受客户端直接提交的号码作为已验证号码。

客户也可以先保存称呼、暂不授权手机号。H5 可查看已有资料和保存称呼，手机号授权需要在微信小程序中操作。预约信息仍可手工填写；手工联系号码不会被当成微信已授权号码。

预约确认页会预填已保存的称呼和已授权手机号；客户手工修改过的本次预约联系人不会被后台预填覆盖。个人资料更新不修改历史预约，不会把其他微信号的历史订单归入当前微信号。

## 数据关联与会员标识

- 微信登录账号以该小程序内的 OpenID 去重。
- 手机号授权成功后，按手机号关联唯一 `customer_profile`；同号已有大众点评或会员档案时使用原档案，保留会员等级、原姓名、共享提示及门店私有跟进。
- 小程序称呼单独存储。原有主档姓名与小程序称呼不同，后台会同时显示，授权流程不会用新称呼覆盖导入的主档姓名。
- 新建档案默认“非会员”。会员/非会员及会员等级由总部维护，客户接口不接受会员字段。未授权号码时，不向客户返回同号历史档案或会员资料。
- 来源按记录累积，支持“小程序”“大众点评”“微信”“电话”“到店”“资料导入”。来源可同时有多个，不是二选一，也不用于判断会员身份。
- 大众点评来源来自现有大众点评导入和预约来源；本次不会自动连接点评商家账号，也不会新增任何预约或发送通知。

后台“客户档案”支持姓名/称呼/手机号搜索、会员状态筛选、来源筛选及分页。未关联门店的注册客户只对总部可见；门店账号继续只看本店关联客户。完整电话默认脱敏，有 `appointments:phone` 权限时点击查看并记录审计。总部导出继续使用原有独立权限，不包含私有跟进内容。

维护主档与会员标识需要总部账号同时有 `customers:read`、`customers:write`、`customers:master` 权限；门店有 `customers:write` 时只能维护本店私有跟进，不能更改会员或来源。

## 升级方式

Java 累计更新自动执行 Flyway V9，新增：

| 表 | 用途 |
| --- | --- |
| `customer_account` | 微信登录时间、客户称呼、资料用途同意时间、手机号验证时间及主档关联 |
| `customer_source` | 一位客户的多个来源与首次/最近记录时间 |
| `customer_phone_receipt` | 已成功处理的手机号授权 code 的 SHA-256 摘要，用于防止重复写入 |

V9 为已有微信账号补齐登录记录，为已有门店客户、预约和点评客户关联补齐来源。旧数据缺少实际首次/最近登录时间，因此迁移时以账号创建时间作初值，之后新登录更新最近登录时间。已有客户、会员和预约内容继续保留；不会通过手填预约号码自动把微信账号绑定成手机号已授权。

**此前已初始化的门店、品项、示例调理师与图片无需再次导入。** 本功能是结构升级与客户操作时写入，不依赖初始化脚本。
