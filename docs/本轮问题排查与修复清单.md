# 裕和堂预约系统：本轮问题排查与修复清单

核查日期：2026 年 11 月 4 日。

本轮围绕总部全店管理、门店独立操作、客户预约到后台处理、改约名额、消息配置、资料导入和权限入口进行排查。下表区分了本轮修复与已经通过的回归验证，微信真机与外部 PMS 接入的验证边界见文末。

## 已修复的问题

| 位置 | 发现的问题 | 修复后的行为 |
| --- | --- | --- |
| 总部与门店切换 | 请求返回顺序和门店选择顺序不一致时，旧门店数据可能覆盖新门店页面；弹窗、筛选和分页也可能沿用旧状态。 | 工作台、预约、客户、调理师和消息页面按账号与门店重新加载；列表请求校验请求序号，旧响应不再覆盖当前页面。切店关闭原操作弹窗并重置对应状态。 |
| 消息中心 | 总部选择“全部门店”时，接收人配置会默认取第一家店，容易误把上海店当作总部设置。 | 全部门店只汇总消息记录；必须主动选店后才能配置该店接收人。切换门店后清除原接收账号和绑定链接，仅列出本店有效账号。不存在的门店返回 404。 |
| 门店公开资料 | 修改名称或状态保存后，顶部下拉与总部总览可能仍使用旧数据。 | 保存后刷新后台门店主数据；名称、状态、总部总览和客户接口保持一致，不改变总部的账号范围。 |
| 前台代约 | 总部全店视图会默认第一家店；切换门店后可能残留原项目和时段。 | 总部须明确选择接待门店；换店清空原项目、时段和意向老师；项目与可用日期根据该店规则加载。关闭在线申请的门店不出现在在线代约列表。提交支持防重复操作与幂等重试。 |
| 客户选项目 | 更换门店时，原项目可能已被新门店停用，但旧选择仍保留。 | 新门店未开放该项目时清除原选择，须重新选择本店支持的项目。 |
| 客户与后台改约 | 当前预约占满时段后，页面把自己占用的名额也当成他人占用，导致原时段无法选择。 | 新增按预约查询改约名额的接口；校验客户身份或后台门店权限后，计算名额时排除该预约自身占用。公开查询不允许任意排除预约。 |
| 改约日期和时间 | 换日期可能残留旧时间；旧日期请求晚返回会覆盖新日期；后台改约天数固定为 7 天。 | 换日期立即清空原时间，等待新日期结果；忽略旧请求；按门店提前可约天数限制日期，并按同行人数筛选名额。H5、后台和原生小程序改约页均已调整。 |
| 后台预约处理 | 预约更新后，弹窗中实际老师和日期可能仍沿用修改前的值。 | 随预约版本同步表单；改约后实际分配清空、状态回到待门店确认，后台显示新的日期和待分配状态。 |
| 营业时间与时段生成 | 结束营业时间接近午夜时，使用 LocalTime 累加间隔可能跨到零点，持续循环。 | 按当天整数分钟生成时段，到营业结束即停止，不跨日回绕。 |
| 临时停约与日期输入 | 不存在的开始时段可能被保存；错误日期可能产生服务端异常；保存后缺少临时安排列表。 | 校验日期范围、HH:mm 格式、营业时间和时段间隔；非法输入返回 400。展示已保存的未来临时安排并支持回填编辑。已有有效预约仍受保护。 |
| 调理师资料导入 | 更新资料可能把已有照片覆盖为默认图片；跨店更新在预检阶段不够明确。 | 导入保留已有照片及未导入字段。跨店记录在预检阶段明确拦截，需通过调理师管理的转店流程处理；提交阶段保留并发校验。 |
| 店长账号维护入口 | 页面提供修改店长自身或其他店长的入口，提交后却被服务端禁止。 | 门店店长只显示有权维护的本店前台账号入口；角色明细按权限只读，角色修改仍由服务端拦截。 |

本轮浏览器实际走通：客户提交申请 → 状态为待门店确认 → 总部及本店查到记录 → 门店分配调理师并确认 → 客户看到确认结果 → 客户改约 → 重新待人工确认且清空实际分配 → 客户取消 → 后台同步取消并释放人数名额。

另外实际模拟了余姚路请求延迟、先切换百乐门再放回旧响应的情况，确认不会串回余姚数据；实际保存门店名称，确认顶部范围、总部总览与客户接口同步；以百乐门账号请求余姚预约和改约名额均返回 404，店长直接请求修改角色返回 403。

后端测试还覆盖重复提交、并发不超卖、客户预约归属、调理师跨店选择和分配限制、转店与历史预约、角色变更后会话失效、已有预约不能静默停约、导入事务、日期输入、深夜营业、消息条件展示以及 PMS 事件字段白名单。
