## 已有门店和首次空库

- 已有门店按编号、完整店名匹配；同名门店保留现有编号。编号与店名冲突或店名重复时停止，避免改错门店。
- 保留已有门店账号绑定、服务项目配置、启用状态、在线预约开关、预约规则和坐标。展示营业时间与预约时段为不同字段，预约时段仍由“门店与时段”维护。
- 缺少的门店通过现有 XLSX 导入接口创建，在线预约默认关闭。请先配置项目、调理师及预约时段，再开启在线预约。
- 其他门店、客户、订单、预约和角色权限不在导入范围内。导入成功后门店资料直接生效，无需重新发布 Java、管理后台或小程序。
- 再次执行会把上述公开字段恢复成本包内容；照片按内容校验复用，已经一致的门店不再写入。门店后续自行维护后，不应把本包作为定时同步任务。

## 服务器操作（Java 已启动）

使用 Ubuntu 自带 Python 3，无需安装额外 Python 库。上传初始化 ZIP 及 `.sha256` 到 `/home/ubuntu`。不要上传到网站的公开目录。

```bash
cd /home/ubuntu
sha256sum --check yuhetang-official-stores-20261107.zip.sha256
python3 -m zipfile -e yuhetang-official-stores-20261107.zip .
cd yuhetang-official-stores-20261107
```

先预览，按提示输入**这套管理后台总部账号的密码**，不是 MySQL、1Panel 或服务器密码。默认账号为 `admin`，修改过账号则加 `--username 你的总部账号`。

```bash
python3 tools/initialize-official-stores.py --base-url http://127.0.0.1:8790
```

确认显示的 9 家店后执行写入，再输入同一个管理后台密码：

```bash
python3 tools/initialize-official-stores.py --base-url http://127.0.0.1:8790 --apply
```

成功会显示 `Verified: ...`。刷新管理后台的“门店与时段”和“图片素材”查看结果。脚本只连接这套 Java 的后台接口，不连接或修改服务器其他 MySQL 数据库。若 Java 的宿主机映射端口不是 8790，只修改 `--base-url` 中的端口；HTTP 仅允许本机地址，远程执行需使用完整 HTTPS 域名。

执行前备份存入当前解压目录的 `backups/official-stores/<时间戳>/before.json`；`report.json` 记录创建、更新及图片上传结果，可用 `--backup-dir /你的非公开目录` 改变备份位置。已有资料可依照 `before.json` 在后台恢复，新增门店及素材不会自动删除。

每个接口请求分别提交，不是跨文件、跨门店的一次数据库事务。出现失败立即停止，并把已完成步骤记录为 `incomplete`；依据报告排查后可重新运行。导入期间尽量暂停门店公开资料的人工修改；脚本会检测已观察到的并发修改，但接口本身没有版本锁。

## 本地操作与数据来源

在后端仓库运行：

```powershell
python tools/initialize-official-stores.py --base-url http://127.0.0.1:8790
python tools/initialize-official-stores.py --base-url http://127.0.0.1:8790 --apply
```

`initial-data/official-stores/stores.json` 保留官网详情页、原图链接、照片 SHA-256 和尺寸。更正资料后可重新执行；修改图片时需要同步更新文件大小和 SHA-256。初始化不增加 Java 启动时的自动灌数行为，生产环境继续保持空业务库首次启动的约定。
