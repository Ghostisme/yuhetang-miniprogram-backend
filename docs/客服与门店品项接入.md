# 客服与门店品项接入

## 门店操作

店长或前台登录后进入原有“品牌与内容 → 养护项目”，沿用原来的内联编辑表单和右侧实时预览，不新增独立菜单。可新增本店专属项目，也可编辑品牌基础项目在本店的名称、简短说明、分类、参考时长、图片、详细介绍、步骤和上下架。点击“保存到小程序”后，同次修改全部保存成功才会生效，并立即用于本店展示、客户预约、前台代约及老师可服务项目选择，不需要总部发布品牌草稿。总部在此选择具体门店即可维护该店项目；选择“全部门店”时保留原有品牌草稿和发布流程。

总部进入该菜单时先选择门店，也可在顶部切换范围。品牌基础项目没有本店覆盖时沿用已发布品牌内容；旧的门店禁用项目配置继续有效。总部停用品牌项目后，门店不能自行恢复上架；本店专属项目不进入其他门店。项目下架保留历史预约中的项目快照。保存携带版本，旧表单返回 409，需要重新加载再编辑。

“客户沟通”接收两种独立标识的会话：

| 渠道 | 客户入口 | 管理端行为 |
| --- | --- | --- |
| 在线咨询 | 原客服入口旁的“在线咨询”，进入项目自己的聊天页 | 每 2 秒刷新、双向文字沟通、历史、已读和处理状态 |
| 微信客服 | 首页、养护详情、门店详情、预约表单/结果、我的预约及咨询页中的“微信客服”按钮 | 直接打开微信原生会话，微信回调入库，后台在微信允许的窗口及条数内回复 |

门店仅能查看及回复本店；总部可查看全部门店，并把尚未归店的会话转交门店。客户按登录身份访问自己的会话，手机号不授予历史会话访问权。新消息自动重新打开已处理会话。后台其他菜单也显示未读数，页面开启时约每 5 秒更新；桌面提醒需主动授权且浏览器保持运行。

## 微信原生客服配置

在线咨询使用本系统客户 JWT 和 API。微信客服使用原生 `button open-type="contact"`，无需先打开项目聊天页或等待本系统登录；用户在微信客服会话内收发消息。网页版 H5 继续使用在线咨询，微信原生会话需在微信小程序内体验。微信原生客服接待另需以下配置：

1. 后端设置 `WECHAT_APP_ID`、`WECHAT_APP_SECRET`，只通过服务器环境变量传入。
2. 在小程序管理平台配置“消息推送”：URL 为 `https://正式域名/api/wechat/customer-service`；设置随机 Token 和平台生成的 43 位 EncodingAESKey，选择安全模式。消息格式支持 JSON/XML。
3. 后端环境变量 `WECHAT_MESSAGE_TOKEN`、`WECHAT_MESSAGE_AES_KEY` 必须与平台一致，重启应用使配置生效。保持 `WECHAT_MESSAGE_ALLOW_PLAINTEXT=false`；明文模式开关仅供明确需要的联调。
4. 确保回调 URL 可被微信公网访问，代理保留查询参数及原始请求体；GET 校验返回 echostr，POST 成功返回 success。不要给此 URL 添加后台登录跳转。接口自身校验签名、时间戳、加密消息及 AppID。
5. 微信平台按要求配置服务器出口 IP 白名单、客服人员及小程序合法域名。小程序 `config.js` 配置正式 HTTPS API，`project.config.json` 使用真实 AppID。
6. 真机从门店详情、预约表单或该店预约记录点击“微信客服”，发送文字或图片；对应门店后台“客户沟通”应收到“微信客服”会话，在窗口内回复并检查微信端实际收到。首页、品牌介绍及“我的预约”页底部的通用入口进入总部客服。

原生按钮通过 `session-from="yht-store:门店ID"` 携带公开门店信息，空门店 ID 表示总部。该值只选择接待门店，不包含客户身份、手机号、令牌或预约资料。服务端只在验签、解密及校验 AppID 后处理微信的进入事件，客户身份取自微信回调的 `FromUserName`，门店必须存在且启用。切换门店立即更新按钮来源；旧进入事件不能覆盖新路由。无需依赖登录接口，也不会为了打开微信客服创建在线聊天会话。旧版 `/api/me/chat/entry` 随机入口继续兼容，仍校验身份和有效期。

微信客户切换咨询门店后，旧门店保留历史但不能继续向这个微信客户发消息。无效或缺失来源不会选择任意门店：优先沿用已知接待路由或最近预约门店，否则进入总部待分配。按钮打开失败时显示重试提示，并保留独立的“在线咨询”入口，不自动跳转替代会话。

当前微信规则：客户主动发消息后可在 48 小时内回复 5 条；仅进入客服会话时可在 1 分钟内回复 2 条。后端按此限制本系统的回复，最终以微信接口受理结果为准。其他客服工具也可能消耗账号窗口或配额。平台规则变化时需要同步更新实现。

后台支持文字回复；客户文字、图片、小程序卡片和进入事件可接收。图片通过有权限的后台接口下载，受微信临时素材有效期限制。其他微信客服工具或微信客服人员在外部工具发出的消息没有同步回调，本后台不能展示那些外部发出记录；请约定实际接待工具。在线与微信渠道各保留会话，不把相同客户的两种消息混为一个线程。

发送状态区分成功、失败及结果待核实。微信网络超时不能视为成功，也不自动重发可能已被微信接收的内容；同一个 clientKey 重试返回原结果。结果待核实应先检查微信端实际送达情况，再决定是否发送新消息。

官方依据：[button 原生客服及 session-from](https://developers.weixin.qq.com/miniprogram/dev/component/button.html)、[小程序客服机制](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/customer-message/customer-message.html)、[接收客服消息](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/customer-message/receive.html)、[发送客服消息及窗口](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/customer-message/send.html)、[消息推送](https://developers.weixin.qq.com/miniprogram/dev/framework/server-ability/message-push.html)。

## 总部配置角色与品牌内容权限

总部管理员登录后进入「角色与权限」，可直接配置内置「门店店长」「门店前台」，也可新建自定义角色。在「用户管理 → 配置用户」中选择所属门店和角色，门店账号始终只能操作该门店；总部范围角色不绑定门店。共享角色的修改影响所有关联账号。若某一家门店需要不同权限，应新建门店角色，再仅分配给该店对应账号。

原有「品牌与内容」的表单、四个页签及实时手机预览继续使用，各项权限的作用如下：

| 授权项 | 页面及操作 |
| --- | --- |
| 预览品牌内容 | 查看首页与品牌、品牌产品及空间相册；门店只能查看已发布版本，不能读取总部未发布草稿 |
| 查看本店养护项目 | 在原「养护项目」页签查看本店目录；只有查看权限时表单只读 |
| 维护本店养护项目 | 编辑名称、时长、图片、介绍、步骤、新增及上下架；保存后直接同步本店展示和预约 |
| 编辑品牌草稿（总部） | 总部选择「全部门店」时编辑原品牌内容表单及保存草稿 |
| 发布品牌内容（总部） | 总部发布内容；仅有发布权限的岗位只可发布服务端已保存草稿，提交自改字段不会改写草稿 |
| 查看 / 上传图片素材 | 分别控制素材列表与上传操作 |

勾选操作权限会自动勾选所需查看权限，取消查看权限会同时取消依赖它的操作。后端也校验和补齐依赖，不能通过直接调用角色接口绕过。门店角色不能授予总部品牌编辑、发布、总部客服分流、角色管理及导入导出等总部专属权限。

菜单、页签、表单和按钮按权限显示，API 独立校验权限和门店归属。无任何模块权限时显示待授权提示。仅有「维护时段规则」权限时可进入「门店与时段」编辑预约规则，门店资料只读。

保存角色后所有关联账号的旧登录立即失效，须重新登录获取新授权。系统内置「总部管理员」保留完整权限用于管理；其他总部岗位请创建自定义角色。应用重启不会恢复已经撤销的角色授权。`V3__rbac_content_permission_labels.sql` 仅调整权限名称及分组，不给既有账号重新授权，也不修改门店或预约资料。

## 权限与数据升级

应用启动时 Flyway 执行 `V2__store_services_and_customer_chat.sql`，增加门店品项及客服表和权限，不删除原门店/预约资料。既有内置总部、店长和前台角色获得 `services:read`、`services:write`、`chat:read`、`chat:reply`；`chat:route` 仅给总部。自定义角色保持原授权，需要总部按岗位勾选新权限。

上线前备份本应用数据库及上传目录，先在本应用测试副本执行迁移与验收。测试使用独立 H2 内存库，没有连接或改动其他本地业务数据库。MySQL 部署及真实微信联调仍需在目标环境验证。

## API 约定

客户及后台接口使用 `Authorization: Bearer TOKEN`，后台另校验权限及门店归属。

| 接口 | 用途 |
| --- | --- |
| `GET /api/stores/{storeId}/services` | 本店已上架目录 |
| `GET /api/admin/stores/{storeId}/services` | 本店管理目录，含下架及版本 |
| `POST /api/admin/stores/{storeId}/services` | 新增本店专属项目 |
| `PUT /api/admin/stores/{storeId}/services` | 原内容表单批量保存 items，事务内校验各项目 version；任一失败则整批回滚 |
| `PUT /api/admin/stores/{storeId}/services/{id}` | 带 version 更新本店项目 |
| `POST /api/me/chat/entry` | 旧版兼容：获取绑定身份及门店的 sessionFrom；新版原生入口无需调用 |
| `POST /api/me/chats` | 用 storeId 打开在线会话；空值为总部 |
| `GET/POST /api/me/chats/{id}/messages` | 查看/发送本人的在线消息 |
| `GET /api/admin/chats` | storeId、status、q、page 筛选；每页 30，会话总数和未读总数 |
| `GET/POST /api/admin/chats/{id}/messages` | 查历史/回复，返回实际发送状态 |
| `PATCH /api/admin/chats/{id}/read` | throughSeq 标记已读；按门店坐席共享已读位置 |
| `PATCH /api/admin/chats/{id}/status` | status 为 OPEN 或 RESOLVED |
| `PATCH /api/admin/chats/{id}/route` | 总部将未归店会话转交 storeId |
| `GET /api/admin/chats/{id}/messages/{messageId}/image` | 权限校验后下载客户图片 |
| `GET/POST /api/wechat/customer-service` | 微信签名校验和安全消息回调 |

消息初次加载最近 100 条；`before=首条seq` 向前翻页，`after=最后seq` 按升序增量取后续最多 100 条，直到追上最新。发送体为 `{content,clientKey}`；clientKey 长 8–80，仅字母数字、横线和下划线，同会话同标识重试幂等，改内容返回 409。正文最多 2000 字符及 4000 UTF-8 字节。

## 本地验证

`RbacIntegrationTest` 使用独立 H2 内存库，验证内置门店角色授权与撤销、旧登录失效、跨店隔离、总部专属限制、多角色权限合并、品牌草稿隔离及编辑/发布岗位分离。浏览器权限回归为 `npm run verify:rbac`，只允许指向 `127.0.0.1:18891` 的独立 local 测试服务，并显式设置 `TEST_BASE_URL`、`TEST_API_URL` 和 `TEST_ALLOW_RBAC_MUTATION=1`；会修改测试角色、新建账号和项目。结果写入 `docs/rbac-result.json`。

在本项目 `backend/` 目录执行 `mvn -B -ntp test`。`StoreChatIntegrationTest` 使用独立内存库和模拟微信网关，覆盖门店目录、客户/前台预约、老师项目、跨店权限、会话归属、增量历史、加密回调/验签/去重、路由、窗口与配额、并发回复、失败/未知结果和 V1 旧库升级。它不向微信真实账号发送消息。

在本项目根目录执行 `npm run build`、`npm run check:mini`。浏览器回归也在项目根目录执行 `npm run verify:store-chat`，要求显式设置 `TEST_BASE_URL`、`TEST_API_URL`，仅用于隔离 local 环境；会新增测试项目、预约及会话，结果在 `docs/store-chat-result.json`，截图在 `docs/screenshots/store-chat-*.png`，均忽略入库。

微信开发者工具编译、真实登录与消息收发、HTTPS 回调、正式账号权限及 MySQL 迁移不由 H5 或模拟网关测试代替，需用客户真实配置完成验收。
