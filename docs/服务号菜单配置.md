# 服务号菜单配置

服务号菜单已经通过开发接口管理时，使用本项目管理后台左侧的 **服务号菜单**。无需在微信接口调试工具里手工填写 JSON。

## 日常操作

1. 使用总部账号登录管理后台，点击左侧 **服务号菜单**。
2. 首次打开会在编辑区预填 **在线预约、门店查询、我的预约**，目标为当前小程序。预填不会保存或发布。
3. 点击左侧某个菜单，修改名称，从 **打开的小程序页面** 下拉框选择目标。也可设置网页链接，或把一级菜单改为 **展开子菜单**，再添加二级菜单。使用上下箭头调整顺序。
4. 点击 **保存草稿**。草稿保存到服务器，微信菜单不变。
5. 核对右侧预览后点击 **发布到微信 → 确认发布**。服务器会先读取并备份当前默认菜单，收到微信成功响应后才显示“微信已接受”。稍候重新进入服务号验证三个入口。

**读取微信菜单** 用于核对微信当前配置；读取后可点击 **载入编辑**，再保存、发布。**恢复发布前菜单到草稿** 只恢复本系统草稿，核对后仍需手动发布。

菜单最多 3 个一级菜单，每个一级菜单最多 5 个二级菜单。一级名称建议不超过 4 个汉字，二级建议不超过 8 个汉字；服务端同时校验微信的 16/60 字节上限。小程序页面必须已存在于正式版。若微信另有个性化菜单，本页会提示其数量，本页仅编辑默认菜单。

## 首次接入或更新

分别更新本次 Java API 和管理后台静态文件，小程序客户端无需为菜单功能重新编译。Java 启动时执行 V10 迁移，新增菜单配置表和权限，保留既有业务记录、角色和消息配置。更新前按现有部署流程备份本项目数据库和旧包，不执行首次初始化或删除数据卷。

如果页面显示 **待配置服务号凭据**，在 Java 服务原有运行环境补齐：

```dotenv
SERVICE_APP_ID=服务号的AppID
SERVICE_APP_SECRET=服务号的AppSecret
```

Docker 部署保存环境变量后，使用本轮整体更新入口加 `--reload-env` 重建 Java 容器；普通 `docker restart` 不会读取变更后的 env 文件。在微信开发者平台为该服务号配置服务器出口 IP 白名单，并确认目标小程序已关联。已有服务号模板通知使用相同的环境变量，配置完整时无需重复设置。页面不展示 AppSecret，不要求每次填写凭据。

内置总部管理员升级后拥有菜单权限。自定义总部角色可在 **角色与权限 → 服务号菜单** 分配查看、编辑草稿和发布权限；门店角色不能获得此功能。

发布遇到权限或白名单错误时，页面会保留微信错误码并给出对应说明。发布超时或连接中断时结果可能尚未确认，先点击 **读取微信菜单** 核对，避免反复提交。旧平台仍在自动发布菜单时，需要在旧平台停止菜单同步，以免覆盖新配置；消息推送迁移单独处理。

## 接口与验证范围

本功能使用服务号的稳定版 `access_token`，不强制刷新原消息服务的凭据。普通进入页面和保存草稿不会请求微信。发布只提交用户明确确认的已保存版本；并发修改会返回冲突提示。

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `GET /api/admin/wechat-menu` | 查看 | 读取本地配置及接入状态 |
| `PUT /api/admin/wechat-menu/draft` | 编辑草稿 | 保存 `revision` 和 `menu` |
| `GET /api/admin/wechat-menu/remote` | 查看 | 读取微信默认菜单和个性化菜单数量 |
| `POST /api/admin/wechat-menu/publish` | 发布 | 备份并发布指定 `revision` |
| `POST /api/admin/wechat-menu/restore-draft` | 编辑草稿 | 将发布前备份恢复为草稿 |

参考：[创建菜单](https://developers.weixin.qq.com/doc/service/api/custommenu/api_createcustommenu.html)、[查询菜单](https://developers.weixin.qq.com/doc/service/api/custommenu/api_getmenu.html)、[稳定版凭据](https://developers.weixin.qq.com/doc/service/api/base/api_getstableaccesstoken.html)。

本地接口与浏览器验证使用隔离数据库及模拟微信响应，不能替代正式服务号凭据、IP 白名单、关联关系和手机跳转验收。
