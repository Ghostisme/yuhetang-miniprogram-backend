# 现有服务器资源与部署判断

记录日期：2026-11-05。数据来源为用户提供的当前腾讯云终端输出，不代表持续负载监控或容量压测。

## 当前结论

4 核 / 8 GiB / 50 GiB 的规格本身不排除初期小流量运行，但这台共享主机已经占用大部分内存和磁盘。**当前余量不适合直接启动现有独立 MySQL + Java 部署包作为稳定业务。** 不能把“安装脚本放行”或“进程能启动”当成可长期上线。

不扩容并非只能放弃部署：本轮已定位到 `/www/server/label-studio` 占 19 GiB，是最大的单个目录；`/www/server/data` 为 612 MiB（是否为宿主 MySQL 实际数据目录仍以运行配置为准）。19 GiB 不能直接视为可回收空间，还需分清标注数据、上传文件、依赖环境与缓存，并核对运行中的 Label Studio 是否使用它。即使磁盘能腾出空间，内存也仍需单独解决。现有安装脚本的资源门槛尚未下调，云端没有执行清理或改配。

## 现有包的资源设置与边界

- 新数据库容器：1 CPU 上限，内存上限 1 GiB，buffer pool 256 MiB，最多 40 连接。
- Java 服务：堆最大 512 MiB，metaspace 最大 192 MiB，direct memory 最大 64 MiB，进程的 systemd 内存上限 1 GiB。
- 应用数据库连接池 8、HTTP 工作线程最多 64，写操作和大导入设有并行上限。
- 上述是上限配置，不是说两个进程启动就必定各占满 1 GiB；实际启动与峰值驻留内存尚未在这台机器测量。Java 的 `-Xmx` 也不是进程全部内存。
- 安装预检要求可用内存至少 3 GiB、根盘至少 15 GiB 可用。这是本包为初始化、业务增长、备份及现有业务留余量的保守门槛，不是 MySQL 官方最低硬件要求。

按当前快照，距这套预检门槛还差约 **1298 MiB 可用内存**与 **12.6 GiB 可用磁盘**。19 GiB 的 Label Studio 目录是排查方向；目前没有证据说明其中能释放多少，也没有证据说明内存已有相应余量。

MySQL 的 buffer pool 之外还会为连接、表、排序等用途使用内存，不能只把 256 MiB 当成数据库总内存；减少缓冲区也会影响性能。[MySQL 8.4 内存说明](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/memory-use.html)。

## 不扩容时的处理顺序

1. `/www/server`、`/var/lib` 一级占用和运行中容器快照已取得。接下来只读查看 `/www/server/label-studio` 的下一层目录，并核对 `elegant_yalow` 的挂载来源。当前不用清理命令。
2. 如果存在已确认无用、可重新取得的安装包、缓存或过期业务构建，先列出具体对象及回滚影响，再处理；现有 MySQL 数据目录、redo/undo、binlog、容器卷不直接按文件删除。
3. 如有明确空间可回收，重新运行 `df -h /`、`free -m`；不能用“预计可清理”代替实际余量。
4. 只有余量和旧业务峰值经过核对，才考虑单独制作并验证小流量配置。降低连接数、堆、缓存、导入并发可能减少资源需求，但也降低可承载负载；需要测新库初始化、完整预约/微信链路、限流、备份及旧业务资源波动。
5. 若可回收空间不足，或内存长期没有余量，保持本机现有业务，选择独立资源承载新增数据库/应用。没有直接复用旧 MySQL、回退 H2、停旧业务或跳过预检的隐式变更。

如继续排查可回收空间，下一步可执行以下只读命令：

```bash
du -xhd1 /www/server/label-studio 2>/dev/null | sort -h
podman inspect elegant_yalow --format '{{range .Mounts}}{{println .Type .Source "->" .Destination}}{{end}}'
```

第一条只看目录大小，第二条只列挂载关系，不输出容器环境变量。挂载中出现该路径说明至少有容器使用它；未出现也不能单独证明整目录无用，还需核对宿主服务及业务文件用途。现有数据、活动上传目录和仍需恢复的文件不作为可删除对象。

资源耗尽和整机故障仍可能影响同机业务；分开容器与数据库目录只能隔离配置、权限和业务数据。

## 5 万人同时在线

现有包及这台共享主机没有经过 5 万同时在线验收。小流量试运行与该容量目标需要分开评估；短时 CPU 空闲、开启缓存或设置限流都不能证明达标。该目标需要按真实请求频率、预约峰值、通知任务、静态流量和故障恢复要求压测后规划资源。
