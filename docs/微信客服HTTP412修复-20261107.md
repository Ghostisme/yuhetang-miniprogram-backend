# 微信客服 HTTP 412 修复：20261107-225800

## 原因与修复

本地向微信官方客服发送接口提交两次故意无效的测试凭证及空 JSON，不接触真实客户：固定长度请求返回 HTTP 200 和正常业务 JSON（`errcode=40001`）；同样请求改成 `Transfer-Encoding: chunked` 返回 HTTP 412 且响应体为空。

当前 Java 将 Map 直接交给 JSON 转换器流式写入；JDK 客户端在没有已知长度时使用分块请求。修复为先使用 Jackson 序列化成 UTF-8 字节数组，按字节数设置 `Content-Length` 后提交。中文、表情及转义字符均按真实字节计算，不使用字符串字符数。客户订阅消息同样复用该发送方法。

新增真实本机 HTTP 回归测试，测试服务按微信已复现的行为拒绝分块请求。旧代码在该测试报 HTTP 412，修复后通过，并核对完整 JSON 内容和请求长度。保留现有发送幂等及未知结果不自动重发的行为。

参考：[Spring JDK 请求发送实现](https://github.com/spring-projects/spring-framework/blob/v6.2.19/spring-web/src/main/java/org/springframework/http/client/JdkClientHttpRequest.java)、[微信发送客服消息接口](https://developers.weixin.qq.com/miniprogram/dev/server/API/kf-mgnt/kf-message/api_sendcustommessage)。微信接口对两种传输方式的差异来自本次实测。
