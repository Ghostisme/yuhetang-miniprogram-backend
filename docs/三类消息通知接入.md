# PC、微信个人消息、短信通知

后台沿用「消息中心」，按 PC 端消息通知、微信个人消息通知、短信通知展示。总部选择具体门店后编辑该店设置，门店账号只能处理本店。无需增加独立业务菜单。

## 权限和接收设置

- `notifications:read`：查看三类渠道状态、发送记录和筛选；门店短信接收手机号脱敏。
- `notifications:write`：配置通知渠道与接收人；包含查看权限，由总部在「角色与权限」授权。
- 接收设置按门店保存；通过版本号检查并发修改，旧页面不能覆盖新配置。修改设置会停止该店原待发短信，不把旧预约通知转发给新接收人。
- 升级默认保持 PC 和既有微信通知开启，短信关闭；不调整已有角色授权，不自动补发历史阻断消息。

## 三类渠道

| 渠道 | 接收对象与触发 | 接入条件 |
| --- | --- | --- |
| PC 端 | 新预约、状态变化、待确认超时进入后台消息；客户新咨询在客户沟通中提醒 | 对应模块查看权限；电脑桌面提醒需浏览器授权并保持后台运行 |
| 微信个人消息 | 每店一名接收人使用服务号模板提醒；客户使用小程序订阅提醒，两者可独立开关 | 认证服务号凭证、模板映射和本人确认绑定；客户订阅需真实小程序身份、模板和有效授权 |
| 短信 | 门店人员接收预约处理事件；客户接收确认、拒绝、取消、改期和到店提醒 | 腾讯云短信应用、签名、审核通过的通知模板、服务端凭证；后台开启本店渠道并设置门店接收手机号 |

PC 桌面开关保存在当前浏览器并按登录账号区分，控制预约和客户咨询的桌面弹窗，不影响后台的消息记录。关闭浏览器不再运行桌面提醒。

微信个人消息通过官方服务号和订阅机制送达微信接收人。小程序原生客服会话仍在「客户沟通」中接待，微信推送不改变原生客服的消息机制和回复窗口。

## 腾讯云短信配置

服务端 `.env.local` 或部署环境设置以下变量；前端不接触短信密钥。实现使用腾讯云官方 Java SMS SDK，接口版本 `2021-01-11`。

| 环境变量 | 用途 |
| --- | --- |
| `SMS_SECRET_ID` / `SMS_SECRET_KEY` | 具备短信发送权限的腾讯云凭证 |
| `SMS_APP_ID` | 短信应用 SDKAppID |
| `SMS_SIGN_NAME` | 已审核的短信签名 |
| `SMS_STAFF_TEMPLATE_ID` | 门店人员通知模板 ID |
| `SMS_CUSTOMER_TEMPLATE_ID` | 预约客户通知模板 ID |
| `SMS_REGION` | 默认 `ap-guangzhou` |
| `SMS_STAFF_PARAMS` | 模板参数顺序，默认 `storeName,time,eventLabel` |
| `SMS_CUSTOMER_PARAMS` | 模板参数顺序，默认 `storeName,time,status` |

参数按模板 `{1}`、`{2}` 等位置依次填写。允许字段：`storeName`、`serviceName`、`time`、`status`、`appointmentId`、`event`、`eventLabel`。模板文字和参数限制以账号实际审核结果为准；在控制台按该顺序核对后使用真实手机号联调。中国大陆手机号在请求中自动转换为 `+86` 格式。

## 记录与重试

「消息通知记录」可筛选 PC、微信个人消息、短信及发送状态，每页 30 条，每 15 秒刷新。配置表单不会被记录刷新覆盖。

- `AVAILABLE`：已进入 PC 后台消息。
- `PENDING` / `SENDING` / `RETRY`：待发送、发送中或等待重试。
- `BLOCKED`：未配置凭证、模板、订阅、绑定等，未发送。
- `ACCEPTED`：平台接口已受理；不是送达、已读证明。短信同时保存平台流水号。
- `UNKNOWN`：短信调用结果不明确，暂停自动重发，先在短信平台核实。
- `CANCELLED`：渠道关闭、短信设置变更或预约状态已更新，停止旧通知。
- `FAILED`：明确限流等可重试失败达到三次。

短信任务在发起外部请求前先持久化占用状态，网络层不自动重试。超时或进程中断后请先在平台按时间、接收号码和流水核对；避免重复计费和重复通知。短信这里只记录接口受理，运营商送达回执在腾讯云控制台核对。

## 验证边界

本地可验证配置、RBAC、门店隔离、预约触发、队列去重、三类筛选、短信 SDK 请求及失败处理。短信 SDK 自动化测试通过拦截器模拟平台响应，不向真实号码发送。

真实微信消息和短信送达需正式凭证、模板、用户授权或绑定及真实手机验收。缺少这些资料时后台会显示待配置或未发送原因。
