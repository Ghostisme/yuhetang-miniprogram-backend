# 大众点评客户、订单与预约导入

本轮范围为客户及订单 / 预约记录。文件导入已实现；自动拉取、平台授权和回调尚未连接。页面会显示“文件导入可用 · 自动同步待接入”。以下字段是本项目的导入模板，实际平台导出文件需整理成此格式，不能假定平台直接提供相同列。

## 后台入口

1. 总部在“扩展与配置 → 大众点评数据接入”维护“点评门店 → 本地门店”和“点评品项 → 本店养护项目”映射。客户导入需要门店映射，订单导入还需要品项映射。
2. 进入现有“资料导入”，选择“大众点评客户”或“大众点评订单 / 预约记录”，下载 XLSX 模板、填写纯值、上传预检，再确认导入。每份文件最多 5 MB、5000 行，只读取第一个工作表。列名和顺序须保留，编号与手机号建议设为文本，避免科学计数法和丢失前导零。
3. 客户资料进入现有“客户档案”，按完整手机号匹配基础档案，并建立对应门店的客户关系。保留已有姓名、核实会员标签、外部会员编号和本店私有跟进；不凭导入手机号绑定微信身份。
4. 订单在“预约管理 → 大众点评订单”查看。总部按门店范围筛选，门店只能查看本店记录。历史记录只归档，不占用预约名额。
5. 对“已付款 / 已预约”订单，门店点击“确认到店预约”，核对完整电话、日期、时段及人数，生成来源为“大众点评”的本店已确认预约。之后沿用原预约详情的人员分配、改约、到店及完成流程，并按本店设置生成通知。

本店项目继续在原“品牌与内容 → 养护项目”维护。映射读取本店项目目录；停用品项可归档历史订单，但新建预约仍需满足本店项目启用状态与预约规则。

## 客户模板

| 列名 | 填写要求 |
| --- | --- |
| externalShopId | 已映射的点评门店编号，必填，最多 100 字符 |
| externalCustomerId | 点评客户编号，可空，最多 100 字符；同一门店内不得重复或改绑其他手机号 |
| name | 客户称呼，必填，1–40 字符 |
| phone | 完整中国大陆 11 位手机号，必填；客户文件不接受脱敏号码 |

同一门店、同一手机号的已有客户关系会跳过；其他门店需要独立建立本店关系。未提供客户编号的行仍可按手机号导入，不会虚构平台客户标识。

## 订单 / 预约记录模板

| 列名 | 填写要求 |
| --- | --- |
| externalShopId | 已映射的点评门店编号 |
| externalOrderId | 平台订单编号，必填，最多 100 字符 |
| externalLineId | 订单明细编号，可空；空值归一为 `main`。多明细订单须逐行填写不同明细编号 |
| externalProductId | 已映射的点评品项编号 |
| name | 客户称呼，必填，1–40 字符 |
| phone | 完整手机号、`138****1234` / `138••••1234`，或留空；脱敏 / 空号码在生成预约前必须补全 |
| status | `CREATED` 待付款、`PAID` 已付款、`BOOKED` 已预约、`REDEEMED` 已核销、`CANCELLED` 已取消、`REFUNDED` 已退款；也接受对应中文 |
| amountYuan | 非负金额，单位元，最多两位小数，例如 `88.50`；内部按分保存 |
| headcount | 整数 1–100，可空默认 1；生成预约时还需满足门店的单次人数限制 |
| bookingDate | `yyyy-MM-dd`；历史日期可归档，没有预约时间时与 startTime 同时留空 |
| startTime | `HH:mm`；与 bookingDate 同时填写或同时留空 |
| createdAt | 必填，`yyyy-MM-dd HH:mm:ss`，按北京时间解释；也接受带时区的 ISO 时间 |
| updatedAt | 必填，格式同 createdAt，且不得早于 createdAt；用于识别版本，不能用导入当天时间替代真实来源版本 |

例如，一笔已付款订单暂未约到店时间，可以让 bookingDate 和 startTime 同时留空，再由门店选择本地可用时段。已核销、取消、退款等历史订单也可导入查阅，不能直接据此新建预约。

## 重复、更新和核对规则

- 唯一键是“点评门店编号 + 订单编号 + 明细编号”。同一文件内重复键视为错误；重复上传相同内容会跳过。
- 相同明细的不同内容只有在 updatedAt 严格更新时才能写入。同一版本冲突、旧版本、错误映射、金额或电话等字段异常均阻止整份文件提交，避免只导入部分行。预检只读；提交时重新检查全部数据。
- 已有导入数据的门店映射，以及已有订单的品项映射，不能直接改绑。名称可以修改，映射和订单操作均校验版本。
- 导入订单保留来源字段、内容摘要和批次；批次记录文件名、SHA-256、操作人和新增 / 更新 / 跳过数量，并写入操作审计。
- 完整订单手机号可形成门店客户关系；空号和脱敏号只保留在来源订单中。列表及预检显示脱敏号码。
- 已关联本地预约的订单收到新版本后，标记“平台资料已更新，待核对预约”。门店查看关联预约，按实际接待情况处理后点击“已核对平台更新”。标记核对不会自动取消或改约。
- 同一订单明细重复点击、并发确认或其他操作员再次确认，返回同一个关联预约。生成预约使用现有事务锁、容量、提前天数、人数、完整电话及未完成预约数量校验。

## RBAC 与数据范围

复用总部现有“角色与权限”，升级不增加角色、不恢复已撤销授权。

| 操作 | 现有权限 | 范围 |
| --- | --- | --- |
| 查看点评映射和批次 | integrations:read | 总部 |
| 保存映射、下载模板、预检和导入 | imports:write | 总部 |
| 查看订单列表 | appointments:read | 总部所选门店 / 门店本店 |
| 查看可用时段、生成关联预约、核对平台更新 | appointments:write | 总部所选门店 / 门店本店 |
| 查看导入后的客户 | customers:read | 沿用现有客户档案范围 |

需要维护映射的总部岗位应同时具备 integrations:read 和 imports:write。门店无权执行总部导入或跨店操作。

## 后续自动接入的预留

后端 `DianpingPort` 定义版本 1 的统一入口 `ingest(actor, kind, rows, commit, source)`；当前 XLSX 控制器已通过此入口写入客户和订单。未来取得真实授权、接口或导出样例后，新增适配器将平台数据归一到同一契约，再复用映射、事务、版本去重、审计和预约关联逻辑。自动任务需使用明确的总部服务身份和权限，不能绕过门店范围。

V5 迁移增加点评门店映射、品项映射、客户关联、订单及导入批次表，保留现有业务表。当前没有平台网络客户端、定时拉取或接收回调接口，也没有实际连接大众点评。团购券核销明细、评价和支付对账不属于本轮。
