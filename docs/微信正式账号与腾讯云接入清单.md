## 2. 服务器安装与专用数据库

当前用户快照满足独立包的 **15GiB 可用磁盘、3GiB 可用内存** 预检门槛，安装脚本还会实时复查。使用 `releases/yuhetang-admin-20261107.zip` 和 `releases/yuhetang-java-api-1panel-20261107.tar.gz`，完整命令见 [1Panel 操作说明](../deploy/1panel/README.md)。旧 shared-MySQL、TencentOS 合并包和宝塔路径不用于当前服务器。

1. 安装 1Panel 和 Docker，在面板安装 OpenResty。
2. 上传 API 包及校验文件到 `/root/yuhetang-upload`，校验、解压并执行 `prepare.sh`。
3. 脚本建立专用目录、数据库容器及服务文件，生成数据库密码与 JWT 密钥，不自动启动。
4. 编辑 `/etc/yuwatang-reservation.env`，先填写 `ADMIN_PASSWORD`，微信密钥后续接入时填写。保留已生成的数据库凭据，不把密钥发到聊天。
5. 启动 `yuwatang-mysql-isolated.service`，就绪后启动 `yuwatang-reservation.service`，验证本机 API。
6. 在面板创建 mp-admin 静态网站，上传前端 ZIP；建立 booking 接口代理网站，按新包提供的片段配置路由，导入泛域名证书并验收 HTTPS。后台和接口上线后再接小程序。

`SERVICE_*` 是另一路门店人员服务号通知配置，可暂空；短信同样可暂空。客户小程序订阅与原生客服使用 `WECHAT_*`。店长持续接收通知与客户一次性订阅分别配置，不能把客户授权用作店长长期通知。

首次启动自动执行 Flyway，只保留系统权限、总部管理员、空站点配置及订阅模板字段映射。正式库不预置门店、品项、产品、调理师、客户、预约或素材；本地业务数据与上传文件不迁移。用户之后通过“资料导入”逐步导入门店、品项（发布后生效）、调理师和客户；重启保留导入的数据。

## 4. 小程序原生客服

本项目的客户小程序 AppID 为 `wxce054e18303efb8a`。使用现有「客户沟通」模块接待微信原生客服，无需为这条链路接入公众号或服务号。客户订阅消息是另一条发送链路，订阅授权不是客服对话的前提。

实际链路：客户点击小程序「微信客服」→ 微信原生会话 → 微信加密回调到 booking → 本店「客户沟通」→ 店员回复 → 后端调用微信客服接口 → 客户在微信会话内收到回复。

### 4.1 先配置并启动服务器

完成前述独立部署后，在服务器上编辑 `/etc/yuwatang-reservation.env`，以下值必须属于同一个小程序：

```ini
WECHAT_APP_ID=wxce054e18303efb8a
WECHAT_APP_SECRET=填写此小程序的AppSecret
WECHAT_MESSAGE_TOKEN=填写与微信后台一致的Token
WECHAT_MESSAGE_AES_KEY=填写微信后台生成的43位EncodingAESKey
WECHAT_MESSAGE_ALLOW_PLAINTEXT=false
```

Token 自定义 3–32 位英文字母或数字；EncodingAESKey 使用微信后台「随机生成」的值。这三个秘密值只填在服务器和微信后台，不发到聊天、不写入小程序源码。AppSecret 用于调用微信发送接口；Token 和 AESKey 用于接收并校验微信推送，两者不能互相替代。

如果 Java 已安装并在运行，保存配置后执行下面命令，使配置生效；首次部署按第 2 节的顺序启动新数据库及 Java：

```bash
systemctl restart yuwatang-reservation.service
curl --fail http://127.0.0.1:8790/api/health
```

确认 `https://booking.yuhetangtcm.com/api/health` 也能从公网正常访问，再提交微信配置。服务器资源、备案或 HTTPS 尚未就绪时，先完成对应部署步骤。若微信接口要求出口 IP 白名单，应核对实际出口 IP；该服务器已知公网 IP 为 `43.142.125.157`。

### 4.2 在微信后台启用开发者消息推送

登录此 AppID 的微信小程序后台，进入「开发 → 开发管理 → 消息推送配置」，填写：

| 字段 | 内容 |
| --- | --- |
| URL | `https://booking.yuhetangtcm.com/api/wechat/customer-service` |
| Token | 与服务器 `WECHAT_MESSAGE_TOKEN` 一致 |
| EncodingAESKey | 与服务器 `WECHAT_MESSAGE_AES_KEY` 一致 |
| 加解密 | 安全模式 |
| 数据格式 | 建议选 XML；JSON 也已支持 |

URL 使用 **booking 接口域名**；管理后台登录地址仍是 `https://mp-admin.yuhetangtcm.com/admin`。先部署服务并加载密钥，再在微信后台提交验签，并确认推送处于启用状态。该路径同时接收 GET 验证与 POST 消息，不能加后台登录拦截或网页跳转。

直接在浏览器打开回调 URL、未携带微信签名参数时返回参数错误，并不等于回调异常；以微信后台提交验签成功和后续真实消息到达为准。

### 4.3 使用本项目体验版真机验收

项目已有 `button open-type="contact"` 原生入口，以 `session-from="yht-store:门店ID"` 带入门店归属。微信通过已验签的回调提供客户身份；打开原生客服无需先登录本系统。原来第三方的小程序版本不会自动包含本项目入口，需要上传本项目代码为体验版联调，通过后再统一发布。

1. 总部先创建或核对正式门店，给测试店员绑定本店，并授权「查看客户会话」「回复客户消息」。正式新库不会自动带入本地演示账号和门店。
2. 手机打开本项目体验版，进入某家门店详情，点击「微信客服」，主动发送带唯一文字的消息，例如「百乐门店客服联调 20261105」。这里使用原生按钮，旁边的「在线咨询」进入项目自己的聊天页。
3. 本店店员登录 mp-admin 的「客户沟通」，确认出现渠道为「微信客服」的会话，门店和文字正确；再从后台回复。
4. 确认客户手机在微信原生会话中实际收到回复。发送一张图片，确认后台能查看；换另一门店账号，确认不能读取或回复刚才的会话。
5. 客户从另一家门店入口重新进入客服并主动发送消息，确认新消息分配给新门店，旧门店保留历史但不能继续向客户发送。

微信当前窗口规则：客户主动发送消息后，48 小时内最多回复 5 条；仅进入会话而未发送消息时，1 分钟内最多回复 2 条。窗口和配额由微信控制；项目已做校验及发送失败记录。其他工具发送的客服消息不会自动补齐到本项目。

验收标准是「客户真实发送 → 本店后台收到 → 本店后台回复 → 客户手机收到」全部通过。加密回调测试、小程序静态检查、微信配置保存成功，均不能单独证明真实双向收发已经完成。

参见微信官方[接收客服消息与入口来源](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/customer-message/receive.html)、[发送客服消息及窗口限制](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/customer-message/send.html)和[消息推送配置](https://developers.weixin.qq.com/miniprogram/dev/framework/server-ability/message-push.html)。
