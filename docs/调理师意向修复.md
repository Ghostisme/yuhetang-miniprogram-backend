# 调理师意向与示例资料修复

预约页按门店、品项、启用状态、客户可见状态和休息状态筛选老师。2026-11-08 的线上只读检查确认：9 家门店已有 27 位示例老师，但仅关联了中医推拿、扶阳悬灸、香薰足疗、刮痧等少数项目；“对症调理”在各店都没有关联老师。因此选择该项目时，名单只剩“门店安排（不指定）”。

## 修复已有示例资料

`tools/repair-sample-therapists.py` 通过现有管理 API 补齐这一批示例老师与本店已上架独立品项的关联，不新增老师。检查时预计修改 27 条示例资料、补充 273 条关联。执行时以服务器当前数据为准。

仅处理来源为 `local-content-20261108`、保留原门店与原示例姓名、`sample=true`，且可服务项目仍等于旧初始化范围的记录。人工改名、转店、改为真实员工或修改过可服务范围的记录保留并计入跳过数量。开关、休息状态、照片、等级、专长及其他资料均保留；待确认或未上架的品项不会加入。不涉及预约、客户、客服、账号、通知配置或其他业务数据库。

把交付的 Python 脚本和同名 `.sha256` 文件上传到服务器 `/home/ubuntu`，再执行（交付文件名为 `yuhetang-repair-sample-therapists-20261108.py`）：

```bash
cd /home/ubuntu
sha256sum --check yuhetang-repair-sample-therapists-20261108.py.sha256
sudo python3 -B yuhetang-repair-sample-therapists-20261108.py --apply
```

提示 `Headquarters administrator password` 时输入管理后台总部管理员密码，不是服务器或 MySQL 密码，输入不回显。登录名不是 `admin` 时，在最后一行加 `--username 实际登录名`。去掉 `--apply` 只预览，不写业务数据；默认使用服务器本机 `http://127.0.0.1:8790`。

执行前备份至 `/var/backups/yuhetang-therapists/<时间编号>/before.json`，执行进度保存在同目录 `report.json`。每次写入前重新核对资料与本店目录；出现并发修改或失败会停止并保留进度，不自动重试写入或回滚。重复运行只补缺失关联，已经补齐的记录不再写入。

成功末尾为 `SUCCESS: SAMPLE THERAPIST LINKS VERIFIED`。这次修复只更新数据，无需换 JAR、重建容器、上传管理后台或重新审核小程序。完成后重新进入预约，选择本店“对症调理”，应能看到本店可见且非休息的示例老师。

## 真实员工与人工维护

在管理后台“调理师管理”选择门店，编辑老师的“可服务项目”，勾选本店允许接待的项目并保存。候选老师还需要处于启用、向客户展示、非休息状态。该选择记录客户意向，实际接待仍由门店确认；不表示已锁定该老师的排班。
