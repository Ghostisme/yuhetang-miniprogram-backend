# 一期功能与验收清单

基于 v2.3 和本轮确认实现。费用和工期沿用已确认合同，本文件只说明当前代码功能与技术验收方式，不另行修改商务条款。

## 预约主链路

| 步骤 | 已实现行为 | 验收要点 |
| --- | --- | --- |
| 门店与项目 | 展示九店和品牌品项，梅花店电话联系，其他门店按开放项目预约 | 暂停项目不可提交；地址、图片与电话由后台维护 |
| 日期与时段 | 上海时区、提前天数、最短提前分钟、开始时段粒度、营业与停约规则 | 不出现过去时段；名额不足不可提交 |
| 同行人数 | 同门店、同项目、同开始时段，按人数占用名额 | 两人占两个名额；跨品项共享该门店同开始时段容量 |
| 留资 | 称呼、手机号、意向调理师、是否会员、是否到过店、备注及隐私同意 | 调理师可选“门店安排”；会员自述不自动等于后台已核实会员 |
| 调理师所属门店 | 每位调理师绑定一家门店；总部可在编辑资料中调整所属门店，门店账号只能维护本店人员 | 转店后仅在新店供客户选择和前台分配；有未结束且已实际分配的预约时须先重新分配或完成接待；原预约保留原门店，已有老师意向由原店重新沟通；切店清空旧意向、接口拒绝跨店提交与分配 |
| 提交结果 | 状态为“待门店确认”，明确“当前尚未预约成功” | 提交页、结果页、我的预约均不误报接待已确定 |
| 人工审核 | 本店后台查看新单、查看电话、分配实际调理师、确认或填写原因拒绝 | 其他门店无法查看；意向和实际分配分别展示 |
| 客户回看 | 我的预约显示最新状态和实际调理师，支持符合规则的取消与改约 | 改约重新进入待确认；满额改约失败保留原单原名额 |
| 后续处理 | 到店、完成、取消和超过迟到保留时间后标记未到店 | 保留操作历史和版本，重复/过期操作被阻止 |

时段是开始时间人数名额，不是连续服务时长锁床。老师由前台分配；没有实时抢老师、床位/包间匹配、跨店支援排班或每位同行独立选择项目。

## 后台模块

| 模块 | 当前支持 |
| --- | --- |
| 工作台 | 本店/总部真实数据统计、新预约和当日时段概览 |
| 预约管理 | 筛选、分页、详情、来源、代约、人工审核、分配、改约、跟进和状态流转 |
| 门店 | 总部“全部门店”展示九店总览，选择一家后维护图片、电话、地址、营业、门店规则、品项开放、容量例外及停约日期，可返回全部门店 |
| 调理师 | 总部“全部门店”按所属门店分组汇总人员，可筛选单店；编辑或转店只变更该老师，不改变总部查看范围；无人员的门店仍显示；全店视图新增须明确选择所属门店 |
| 客户 | 预约自动关联客户、本店私有跟进、核实会员标签、受控共享查询 |
| 品牌内容 | 项目、产品、空间、品牌故事、首页模块顺序；草稿/发布、三套配色和预览 |
| 素材资料 | 图片上传、XLSX 模板与预检导入、总部预约及客户导出 |
| 用户与角色 | 用户、角色、权限分开管理；总部全量、门店隔离及服务端权限验证 |
| 消息 | 站内消息、浏览器桌面提示、客户订阅、单门店单接收人服务号绑定、发送结果 |
| 审计 | 完整电话查看、导出、账号权限、内容与预约变更记录 |
| 扩展 | PMS v1 事件 Outbox、关闭/启用验证、拉取及幂等 ACK |

## 微信客服和通知验收

小程序工程已放置原生客服入口和订阅授权按钮，后端已实现微信登录、客户订阅发送、认证服务号个人接收绑定与模板发送适配。缺少真实账号配置时会展示或记录条件未满足。

需客户账号完成后验收：客服真实会话；客户授权后的状态通知；门店新预约服务号通知；管理员解绑后不再发给原人员；电脑通知授权与运行状态。浏览器关闭后不承诺桌面提示，微信接口受理不代表用户已读。

| 总部门店范围回归 | 管理后台仓库 `docs/therapist-store-result.json`；核对全店人员与门店分组、编辑上海老师后百乐门仍可见、转店保留全店范围、门店总览及门店账号隔离；测试后恢复老师原始资料 |
| 原生源码检查 | 小程序仓库 `npm run check:mini`；JSON/JS/WXML 结构、事件绑定、提交控制器及待确认文案，不能代替微信官方编译 |
| 页面截图 | 管理后台仓库 `docs/screenshots/`，均为实际运行的 H5 / 管理后台截图 |

正式交付前还需：替换示例和占位资料，完成客户专属账号和 HTTPS 环境配置，微信开发者工具编译/真机联调，正式数据库验证、备份、客户验收和提审发布。H5 客户预览已真实连接数据库，不等同正式小程序已经上线。

一期不包含支付、团购券核销、订单收费、会员储值积分、财务 ERP、现成 PMS 业务接入或自建即时聊天系统。
