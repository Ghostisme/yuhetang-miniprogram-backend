# 客服会话接入、交接与结束

本次将会话分为待接入 `OPEN`、接待中 `ACTIVE`、已结束 `RESOLVED`。微信原生客服和小程序“在线咨询”共用后台接待规则；两种渠道各自保留聊天记录。

## 接待规则

| 当前状态 | 可以操作 | 后续状态 |
| --- | --- | --- |
| 待接入 | 有本店回复权限的员工点击“接入会话”；总部可将总部待分配会话转交门店 | 接待中 |
| 接待中 | 当前接待人回复、结束或退回待接入；总部具有客服分流权限的账号可主动退回待接入 | 已结束或待接入 |
| 已结束 | 查看历史记录 | 保持已结束，不能由后台重新打开 |

同一会话同时只能有一位接待人。两个账号同时点击接入，只有一个成功；其他账号不能越过接入步骤发送回复。退回待接入会清除原接待人，新接待人必须重新接入。各门店只能操作本店会话；总部的接管操作也必须先明确退回待接入。

“结束对话”先二次确认。后端拒绝对已结束会话接入、回复或重新打开，结束时间、结束人及聊天历史保留。正在发送中的微信回复未返回结果时不能结束或交接，避免出现一边发送一边关闭的情况。发送记录长时间停在发送中会转为结果未确认，不自动重发。

刷新、重新进入页面、晚到的轮询结果和重试接入请求，都不应把已结束会话恢复成接待中。旧客户端尝试回复已结束会话也会被服务器拒绝。

## 客户再次咨询

- 在线咨询：原会话显示“本次咨询已结束”，保留记录，隐藏输入框。客户点击“发起新咨询”后创建新会话，后台重新排入待接入。重复点击或重试不会创建多个同时有效的会话。
- 微信原生客服：只重新打开微信客服窗口，不重开已结束会话；客户实际发送新的文字、图片或小程序卡片后建立新的待接入会话。回调中早于结束时间的延迟消息作为历史记录处理，不重新激活旧会话。
- 客户的新咨询不会沿用原会话的接待人，客服需再次点击接入。旧会话继续出现在“已结束”筛选中。

这里管理的是本系统的会话和回复权限。微信原生客服窗口、微信官方客服工具中的人员绑定不由这几个接口关闭。如果旧客服账号仍在微信官方客服工具里接待，需在该小程序微信后台移除相应客服人员；本系统不会自动撤销其官方账号资格。

## 数据迁移与更新

启动时自动运行 Flyway V8 Java 迁移：增加接待人、接入时间、结束时间、结束人及有效会话标记，替换原来限制“一位客户永久只有一个会话”的唯一索引。新的索引允许多条已结束历史，同一客户、渠道、门店最多一条有效会话。

已有聊天和门店数据不清空。原已结束记录仍是已结束；原进行中 `OPEN` 记录归入待接入，更新后由员工接入一次。V7 通知迁移也包含在累计版本中，未升级过的服务器按顺序执行。

更新顺序为：备份本业务库和旧前端 → 更新 Java → 上传后台静态文件 → 编译小程序。使用现有独立 MySQL `127.0.0.1:3307/yuwatang_reservation`，不另装数据库，不更换 OpenResty 或证书。

V8 改变了会话约束和状态契约，前后端应成套更新。激活脚本保留旧 Java 容器，但这不等于撤销数据库迁移；新版本已经接待出新会话后，不能只启动旧 JAR 作为完整回退。需要恢复更新前本项目数据库备份并恢复匹配的前后端，不能恢复整个 MySQL 实例或清空其他库。MySQL DDL 不能依靠应用事务自动撤销，迁移中途失败应先保留日志、核对迁移状态，再处理本项目备份。

## 验收步骤

1. 客户发一条新的咨询。后台应显示“待接入”，回复框不可编辑；点击接入后显示当前接待人，可回车发送，Shift+Enter 换行。
2. 用第二个有本店权限的员工账号打开同一会话。应显示第一位接待人，不能直接接入或回复。由第一位客服退回待接入后，第二位客服接入并回复；原客服不能继续发送。
3. 当前接待人点击结束并确认。后台应为已结束，不能再接入或发送；客户在线咨询页轮询后移除输入框。刷新两边页面，状态应保持已结束。
4. 在线咨询客户点击发起新咨询并发消息。应产生新的会话编号，后台再次待接入，旧历史不被重开。
5. 微信原生客服先只打开窗口，确认旧会话未重开；再发送新的客户文字，确认出现新待接入会话。接入后回复一次，检查客户手机实际收到。
6. 检查跨店隔离：本店账号不能查询或操作另一门店会话；总部转交仅针对总部待分配且待接入的会话。
